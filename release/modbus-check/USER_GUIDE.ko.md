# Modbus Check 사용 가이드

Modbus Check는 Excel에서 작성한 주소맵을 불러와 통신 확인과 기록으로 이어가는 BMS·MES 실무용 무료 도구입니다. 이 가이드는 프로그램의 Excel 양식에 주소·자료형·설명·비트 설명을 준비하고, 미리보기·가져오기 후 실제 수신값을 확인해 트렌드와 CSV·Excel 기록으로 정리하는 방법을 안내합니다.

현재 공개 버전은 **0.2.0-rc.11 사전 공개 시험판(prerelease)**입니다. [공식 릴리스](https://github.com/oryx-system/ModbusCheck-Releases/releases/tag/v0.2.0-rc.11)는 2026-10-22 05:19:28 UTC에 게시됐습니다.

[Windows x64 설치 파일 — ModbusCheck-0.2.0-rc.11-Setup-win-x64.exe](https://github.com/oryx-system/ModbusCheck-Releases/releases/download/v0.2.0-rc.11/ModbusCheck-0.2.0-rc.11-Setup-win-x64.exe)를 받고 [공식 SHA256SUMS.txt](https://github.com/oryx-system/ModbusCheck-Releases/releases/download/v0.2.0-rc.11/SHA256SUMS.txt)와 대조하세요. 릴리스에 고지된 설치 파일의 SHA256은 다음과 같습니다.

```text
dd63d97fba5b375dc942ad270b5043f57cfd61f6e6e2df9f43a08a40b281d185
```

설치 EXE와 VBA는 미서명입니다. 공식 Node.js 24.22.1 보안 수정판을 포함합니다. 다른 PC의 기본 Office 환경과 조직별 매크로 정책은 미검증이며 일반 보안 알림은 그대로 적용됩니다. 기존 사용자 파일의 출처 표시를 제거하거나 전체 매크로 허용·신뢰 등록을 자동 수행하지 않습니다.

## 어떤 작업에 도움이 되나요?

- 통신 검색으로 승인된 범위의 연결 후보를 확인해 TCP·시리얼 설정을 하나씩 바꾸며 시도하는 수고를 줄입니다.
- 주소별 이름·설명·선택한 자료형과 읽은 값을 함께 대조합니다.
- Binary 비트명·설명을 직접 편집하고 구성 주소의 잠금·해제를 이용해 주소맵을 관리합니다.
- Excel 내보내기→편집→다시 불러오기로 주소맵을 반복해서 입력하는 작업을 줄입니다.
- 트렌드·기록·CSV·Excel 그래프로 시운전 중 값의 변화와 점검 결과를 정리합니다. 현장 시운전 검증이나 인증을 자동으로 마치는 기능은 아닙니다.

## 5단계 시작 순서

1. **설치:** 0.2.0-rc.11 사전 공개의 알려진 한계와 배포처·버전·SHA256을 확인하고 설치합니다.
2. **설정하고 직접 연결:** 장비 매뉴얼에 따라 TCP 또는 시리얼 통신 조건을 정하고 연결합니다. 검색 결과 반영은 자동 연결이 아닙니다.
3. **작은 범위 읽기:** 의미를 아는 주소를 적은 수량으로 읽고 0/1 기준·PDU 주소·자료형·워드 순서를 대조합니다.
4. **기록과 숫자 트렌드 확인:** 읽기 기록을 시작하고 숫자형 값의 변화를 확인합니다. 차트와 파일 기록의 상태를 각각 확인하세요.
5. **내보내고 설정 검토:** 읽기 기록은 CSV·XLSX로, 주소맵과 수신값 백업은 해당 Excel 내보내기로 정리합니다. 주소맵을 다시 불러오면 미리보기·전체 검증 결과에 동의한 뒤 적용합니다. 파일 값을 현재 장비 값이나 쓰기 전 비교 기준으로 취급하지 않습니다.

## Windows 설치와 실행

Windows x64에서 Chrome 또는 Edge를 사용합니다. 화면은 브라우저에서 열리며 장비와의 통신은 같은 PC에서 실행되는 통신 처리 프로그램이 담당합니다. 처음 실행했을 때는 통신 설정을 직접 확인하고 연결해야 하며 장비에 자동으로 연결하지 않습니다.

1. 공개된 배포처에서 설치 파일을 받은 뒤 릴리스에 안내된 파일명·버전과 SHA256을 대조합니다. 해시가 다르면 설치를 진행하지 말고 파일과 배포 정보를 다시 확인합니다.
2. 설치 파일을 실행하고 화면 안내에 따라 설치합니다. 확인되지 않은 배포처의 파일이나 수정된 파일은 사용하지 마세요.
3. 바탕화면 또는 시작 메뉴의 Modbus Check로 실행하고 Chrome 또는 Edge에서 화면을 사용합니다. Node.js는 별도로 설치하지 않습니다. 연결 전에 장비 매뉴얼의 통신 설정과 점검할 주소표를 준비합니다.

설치본의 Windows 지원 범위와 변경 사항은 해당 릴리스의 안내를 확인하세요.

## 점검 준비

먼저 장비 매뉴얼과 점검할 주소표를 준비하세요. 통신 방식, 장비 식별 번호, 주소 기준, 기능 코드와 데이터 형식이 서로 맞아야 같은 값을 읽을 수 있습니다. 장비가 실제로 지원하는 범위를 기준으로 점검 대상을 정하세요.

운영 중인 장비에 연결할 때는 현장 담당자와 점검 범위·통신 주기·쓰기 허용 여부를 먼저 확인하세요. 읽기 작업도 장비와 네트워크에 통신 부하를 줄 수 있으므로 작은 범위부터 확인하는 것이 좋습니다.

고객의 실제 주소표나 운전 데이터는 공개 문의에 첨부하지 마세요. 오류를 재현할 수 있는 최소한의 검수용 데이터로 설명하고, 접속 정보와 장비 식별 정보는 가려 주세요.

## 통신 연결

### Modbus TCP

장비의 IP 주소, 포트와 Unit ID를 확인하고 TCP 연결 정보에 입력하세요. IP 주소는 접속할 장비 또는 게이트웨이를 가리킵니다. 게이트웨이를 사용하는 경우 Unit ID가 뒤쪽 장비를 구분할 수 있으므로 IP가 같다는 이유로 같은 장비라고 판단하지 마세요.

연결되지 않으면 PC와 장비의 네트워크 대역, 케이블, 방화벽과 장비의 Modbus TCP 설정을 확인하세요. 운영 네트워크의 설정을 임의로 바꾸지 말고 담당자와 확인하세요.

### 시리얼 RTU·ASCII

장비가 연결된 COM 포트와 장치 ID, 전송 속도, 패리티, 정지 비트를 맞추세요. 전송 속도는 최대 115200 baud, 패리티는 None·Even·Odd, 정지 비트는 1 또는 2를 지원합니다. RTU는 데이터 8비트, ASCII는 7 또는 8비트를 사용합니다.

포트 번호는 Windows에서 인식한 번호를 기준으로 선택하고, 다른 프로그램이 같은 포트를 사용하고 있는지도 확인하세요. COM 포트 목록을 확인하는 것만으로 포트를 열거나 장비에 연결하지는 않습니다.

USB 시리얼 변환기나 RS-485 배선을 사용할 때는 드라이버, 배선 방향과 장비 매뉴얼의 통신 조건을 확인하세요. 프로그램의 시리얼 지원이 모든 변환기·드라이버·장비 조합의 현장 검증을 뜻하지는 않습니다.

## 주소와 값 확인

장비 주소표의 표기와 통신 요청에 사용하는 주소는 다를 수 있습니다. 주소의 시작 기준과 기능 코드가 맞는지 먼저 확인하고, 장비에서 의미를 알고 있는 값으로 대조하세요.

일반적인 참조 주소 표기는 다음과 같습니다. 실제 장비가 같은 규칙을 사용하는지는 매뉴얼로 확인하세요.

| 장비 주소표의 예 | 읽기 대상 | 기능 코드 | 첫 항목의 PDU 주소 |
|---|---|---|---|
| 00001 | Coil | FC01 | 0 |
| 10001 | Discrete Input | FC02 | 0 |
| 40001 | Holding Register | FC03 | 0 |
| 30001 | Input Register | FC04 | 0 |

PDU 주소는 통신 요청에 실리는 주소이며 지원 범위는 0~65535입니다. 프로그램의 주소 기준을 0으로 선택하면 입력한 주소를 그대로 사용하고, 1로 선택하면 입력한 주소에서 1을 뺀 값을 사용합니다. 예를 들어 첫 항목을 1로 표기한 장비에서 주소 기준 1과 입력 주소 1은 PDU 주소 0을 가리킵니다. 시작 주소뿐 아니라 요청한 수량의 마지막 주소도 범위 안인지 확인하세요.

장비 주소표의 40001이 FC03 영역의 첫 항목이라는 뜻이라면 PDU 주소는 0입니다. FC03을 선택하고 주소 기준 0에서 시작 주소 0, 또는 주소 기준 1에서 시작 주소 1을 입력합니다. 요청 전의 주소 미리보기에서 실제 요청 주소가 0이고 참조주소가 40001인지 확인하세요.

주소 표기의 ‘Modbus 참조주소’와 ‘Offset’은 화면에서 주소를 나타내는 방식입니다. 이 표기를 바꿔도 시작 주소 입력을 자동으로 40001에서 0으로 바꿔 해석하지 않습니다. 이 예에서 시작 주소에 40001을 입력하면 기준 0에서는 PDU 주소 40001, 기준 1에서는 PDU 주소 40000을 요청하게 됩니다. 접두 숫자를 포함한 참조 주소와 실제 주소 오프셋을 혼동하지 마세요.

값이 예상과 다르면 주소를 바꾸기 전에 데이터 형식, 여러 레지스터를 조합하는 순서와 장비의 표현 규칙을 함께 확인하세요. 표시값만 보고 설정을 확정하지 말고 장비 매뉴얼·장비 화면과 비교하세요.

## 데이터 형식과 레지스터 순서

Coil과 Discrete Input은 1비트의 ON/OFF 값입니다. 레지스터 값은 장비가 정의한 형식으로 해석해야 합니다. 같은 원시 레지스터라도 선택한 형식이 다르면 표시값이 달라집니다.

| 형식 | 용도 |
|---|---|
| Unsigned 16 / Signed 16 | 16비트 부호 없는 정수 / 부호 있는 정수 |
| Unsigned 32 / Signed 32 | 2개 레지스터를 조합한 32비트 정수 |
| Float 32 | 2개 레지스터를 조합한 32비트 실수 |
| Unsigned 64 / Signed 64 | 4개 레지스터를 조합한 64비트 정수 |
| Float 64 | 4개 레지스터를 조합한 64비트 실수 |
| Hex / Binary | 원시 값의 16진수 / 비트 표현 |
| Hex / ASCII, ASCII String | 문자 데이터를 확인하는 표현 |

여러 레지스터를 조합할 때는 장비의 워드·바이트 순서를 확인하세요. 프로그램은 ‘ABCD · 기본’, ‘CDAB · 워드 교환’, ‘BADC · 바이트 교환’, ‘DCBA · 전체 역순’을 제공합니다. 값이 작거나 특정 패턴일 때는 잘못된 순서도 그럴듯하게 보일 수 있으므로 의미를 아는 여러 값으로 확인하세요.

32·64비트 값이나 여러 레지스터를 쓰는 문자열은 하나의 묶음으로 관리합니다. 구성 주소에 별도의 이름·자료형을 지정하거나 일부 워드만 쓰는 작업은 제한됩니다. 주소별 별칭과 비트 메타데이터는 보존하며 묶음의 크기를 줄이면 남은 주소를 다시 사용할 수 있습니다.

### 여러 레지스터의 ASCII 문자열

ASCIIBytes는 문자열의 바이트 수입니다. 필요한 16비트 레지스터 수는 바이트 수를 2로 나누고 올림한 값입니다. 예를 들어 20바이트는 10개 레지스터를 사용합니다. 문자 수와 바이트 수를 혼동하지 마세요.

문자열 쓰기는 전체 문자열을 여러 워드의 쓰기 초안으로 준비합니다. 확인 화면에서 홀수 바이트 길이의 채움 바이트, 워드 순서, 실제 전송할 워드와 바이트를 함께 검토한 뒤 진행하세요. 묶음의 일부 워드를 별도로 쓰는 방식으로 문자열을 수정하지 마세요.

### 소수 자리와 Scale/Range

Float 값의 소수 자리는 자동 또는 0~6자리에서 선택합니다. 새 설정의 기본은 3자리입니다. 표시를 위해 반올림해도 원시 값이나 쓰기 초안은 바뀌지 않으며, 표시 자릿수 변경만으로 장비에 값을 쓰지 않습니다.

Scale Low/High, Range Low/High와 Unit은 주소맵과 함께 보관하는 메타데이터입니다. 이 항목에 값을 입력해도 원시 값이 자동으로 공학 단위로 환산되지 않습니다. 장비가 제공하는 값의 단위와 변환 규칙은 매뉴얼과 알려진 기준값으로 대조하세요.

## Binary 비트 이름·설명과 Excel 왕복

16비트 Binary는 Bit0부터 Bit15까지 각 비트의 상태를 확인하고 개별 비트의 쓰기 초안을 편집하는 데 사용합니다. Bit0은 최하위 비트입니다. 장비에서 읽은 상태와 편집 중인 초안을 구분해 보세요. 비트별 이름과 설명은 장비 주소표에 맞춰 작성합니다. 이름·설명이나 입력·표시 방식을 바꾸는 것만으로 장비에 쓰지 않습니다.

주소맵을 Excel로 내보내고 편집한 뒤 다시 불러올 수 있습니다. Binary 타입과 비트별 표시·이름·설명이 왕복되도록 지원합니다. 편집용 XLSM의 주표에서 `Bit 0:`부터 `Bit 15:`까지 비트명·설명을 직접 입력할 수 있습니다. 실제로 사용할 파일은 다음 순서로 확인하세요.

1. 원래 주소맵을 별도 파일로 보관한 뒤 Excel로 내보냅니다.
2. 편집용 XLSM에서 주소맵의 이름·설명과 `Bit 0:`~`Bit 15:`의 비트명·설명을 편집하고 저장합니다. 수식처럼 보이는 이름도 계산식이 아닌 텍스트로 보존합니다.
3. 파일을 다시 불러와 주소·타입·워드 순서와 Bit0~Bit15의 이름·설명을 원본과 대조합니다.
4. 장비 설명서와 의미를 아는 값을 기준으로 읽기 결과를 다시 확인합니다.

주소맵을 불러오는 것과 장비에 값을 쓰는 것은 별도 작업입니다. 파일을 불러왔다는 이유만으로 장비 설정이 바뀌었다고 판단하지 마세요.

편집용 XLSM에서는 32·64비트 값과 ASCII 문자열이 차지하는 구성 행을 잠그거나 해제합니다. 묶음을 줄여 주소가 해제되면 이전 설명을 복원합니다. 구성 행을 별도의 값처럼 덮어쓰지 말고 시작 행의 자료형과 길이를 먼저 확인하세요.

## 숫자형 값의 트렌드

트렌드는 숫자형 값과 HEX·Binary 원시 값의 변화를 확인하는 데 사용합니다. ASCII 문자열은 트렌드 대상에서 제외합니다. 읽은 문자 데이터를 임의의 숫자로 바꿔 장비 상태를 판단하지 마세요.

계열별 표시 여부·이름·색상, 왼쪽 또는 오른쪽 축, 값의 표시 범위를 설정할 수 있습니다. 시간축은 이동·확대·축소하고 초기 범위로 되돌릴 수 있습니다. 범위를 바꿀 때는 현재 보고 있는 구간과 전체 기록을 구분하세요.

점 크기의 기본값은 0.6px이며 이전 크기의 20%입니다. 0~200% 조절 또는 숨김을 선택할 수 있고 설정을 보관합니다. 작은 점에서도 선택할 수 있도록 선택 영역은 별도로 유지합니다. 점 크기를 바꿔도 선·데이터·기록·시간축은 바뀌지 않습니다.

값의 변화가 예상과 다르면 트렌드 모양만으로 원인을 정하지 말고 태그의 주소·자료형·워드 순서와 읽기 주기를 확인하세요. 장비 화면과 의미를 아는 값을 함께 대조합니다.

## 읽기 기록과 CSV·XLSX 내보내기

읽기 기록은 읽기 완료 시각을 첫 열에 두고 계열별 값을 옆 열에 배치합니다. 같은 읽기 결과는 같은 행에 들어가며 읽지 않은 시점의 값을 임의로 채우거나 보간하지 않습니다.

브라우저의 차트와 PC의 파일 기록은 별도입니다. 파일 기록은 파일을 나눠 저장하는 기능과 파일 크기·개수 제한, 중지·복구를 지원합니다. 차트 화면에 보이는 것만으로 파일 기록 상태를 판단하지 말고 각각의 상태와 저장 위치를 확인하세요.

### CSV

전체 기록 또는 현재 차트 시간 범위를 선택해 내보낼 수 있습니다. 기본은 원시 값의 정밀도이며, 표시 소수 자리를 반영하는 내보내기는 선택 사항입니다.

CSV는 UTF-8 BOM, CRLF 줄바꿈과 필요한 따옴표 처리를 사용하며, 셀 내용이 수식으로 해석되지 않도록 처리합니다. CSV에는 차트가 포함되지 않습니다.

### Excel 파일의 목적 구분

| 파일의 목적 | 포함 내용과 확인할 점 |
|---|---|
| 주소맵 | 주소 정의, 이름·설명·자료형·워드 순서·비트 정보와 메타데이터를 보관합니다. 편집용 XLSM은 주표의 비트명·설명 직접 입력과 구성 행의 잠금·해제를 지원합니다. |
| 수신값 백업 | 특정 시점에 받은 값을 보관합니다. 주소 정의만 담은 파일과 구분하세요. |
| 읽기 기록 | 시간 순서의 기록을 보관합니다. 표시 형식과 원시 값 문자열을 함께 다룹니다. 15자리를 넘는 정수는 Excel의 숫자 정밀도 손실을 피하도록 텍스트로 보관합니다. |

읽기 기록 XLSX에는 선택적으로 Excel에서 편집할 수 있는 기본 XY 차트를 넣을 수 있습니다. 그림으로 붙인 차트와 다릅니다. 표시 범위를 벗어난 값은 차트에서 제외될 수 있지만 원시 데이터는 파일에 남습니다. 차트 모양뿐 아니라 데이터 시트도 확인하세요.

### 표준 양식의 주소 개수 확인

RC11 표준 양식은 PDU 0~1000을 양끝 포함해 고유 주소 1001개를 제공합니다. No와 PDU 주소는 구분하며 Binary 보조 행은 주소 수에 포함하지 않습니다. Holding FC03 또는 Input FC04와 참조 0/1 기반 표시를 선택할 수 있고 기존 기본값은 유지합니다.

주소 개수는 Excel의 전체 행 수나 `No` 열의 마지막 숫자로 세지 않습니다. `No`는 표시 순번이며 PDU 주소가 아닙니다. 비트 보조 행과 서식용 빈 행을 제외하고 실제 PDU 주소의 고유값을 세어 0~1000의 1001개 주소가 있는지 대조합니다.

이 결과는 표준 양식의 주소 목록만 확인한 것입니다. 현재 데이터 내보내기·로그나 전체 PDU 0~65535 범위가 모두 검증됐다는 뜻은 아닙니다. 사용하는 파일의 목적과 실제 주소 범위를 따로 확인하세요.

### 편집용 XLSM과 일반 XLSX 저장

편집용 XLSM은 비트명·설명 직접 입력과 구성 행 잠금·해제 같은 편집 지원 동작을 포함합니다. 이 동작을 돕는 매크로가 파일에 들어 있으므로 편집을 계속할 원본은 별도로 보관하세요.

XLSM의 자동 행 확장 등 매크로 기능은 조직에서 허용한 환경에서 사용하세요. 보안 정책을 우회하지 마세요. 앱이 주소맵을 불러올 때는 VBA를 실행하지 않습니다.

매크로가 없는 파일이 필요하면 Excel의 일반 ‘다른 이름으로 저장’에서 XLSX 형식으로 저장할 수 있습니다. 이 과정에서 매크로가 제거됩니다. XLSX에서는 매크로로 처리하던 자동 잠금·해제가 실행되지 않으므로 XLSM과 같은 편집 동작을 기대하지 마세요. 저장 후 셀과 서식도 확인합니다. 앱에 별도 전달용 XLSX 버튼이 있는 것은 아닙니다.

실제 Excel에서 일반 XLSX 저장과 매크로 제거 후 인쇄 모양을 대조한 시험을 진행했습니다. 시험한 자료에서는 인쇄 이미지 차이가 없었지만 모든 주소맵과 문서에서 같은 결과를 보장하지 않습니다. 저장 후 파일을 다시 열어 값·설명·서식과 인쇄 미리보기를 직접 확인하세요.

### 파일 불러오기

불러오기 미리보기에서 정의·자료형·범위와 검증 결과를 확인하고 적용에 동의합니다. 전체 검증을 마친 뒤 적용하며 이전 표시 설정 JSON도 지원합니다. 파일의 값을 현재 장비에서 받은 값이나 쓰기 전 비교 기준으로 사용하지 않습니다. 장비에 연결한 뒤 현재 값을 새로 읽어 확인하세요.

### 현재 Excel 작업의 한계

Float64를 선택한 뒤 Excel 전체가 멈춘다는 제보는 아직 재현하지 못했고 해결 여부도 확인되지 않았습니다. 편집용 XLSM과 검토용 설치본의 시험이 끝났다는 사실로 이 제보까지 해결됐다고 판단하지 마세요. 원본 파일을 별도로 보관하고 저장 후 다시 열어 내용과 계산 결과를 대조하세요.

## 읽기 전용 통신 검색

연결 정보를 모를 때는 통신 검색에서 점검할 범위를 직접 지정하고 작업량 미리보기와 확인 절차를 거쳐 실행합니다. 현장 담당자에게 확인한 범위만 입력하고 작은 범위부터 시작하세요.

| 검색 방식 | 지정할 범위 |
|---|---|
| TCP | 선택한 사설 또는 루프백 주소의 같은 서브넷 안에서 연속된 최대 32개 IP와 최대 8개 포트를 지정합니다. 공인 주소·DNS 이름·브로드캐스트·멀티캐스트는 검색하지 않습니다. |
| 시리얼 | 한 COM 포트에서 RTU 또는 ASCII를 선택하고 110~115200 baud의 13개 표준 속도와 통신 조건을 지정합니다. 운영 통신이나 파일 기록과 충돌하는 검색은 막습니다. |

검색은 FC01~FC04 읽기만 사용하며 요청 수량은 1~4, 연속된 PDU 범위는 최대 512개입니다. 전체 시도는 50,000회 이내, 한 번에 한 요청, 최소 100ms 간격으로 제한합니다. 읽기 검색도 통신 부하를 만들 수 있으므로 허용 범위를 넘겨 검색하지 마세요.

첫 정상 읽기 응답을 찾으면 검색을 멈추고 연결 설정을 입력란에 채웁니다. 장비에 자동 연결하거나 값을 쓰지 않습니다. 검색 중 언제든 취소할 수 있습니다.

입력란에 반영된 결과는 연결 전에 다시 검토하세요. 응답이 있었다는 사실만으로 장비의 모델·주소 의미·데이터 형식이 판별된 것은 아닙니다.

## 쓰기 작업 전 검토

쓰기 작업은 장비의 설정이나 출력을 바꿀 수 있습니다. 읽기 점검을 먼저 마친 뒤 대상 장비, 기능 코드, 주소, 데이터 형식과 쓸 값을 확인하세요. 현장 절차에서 허용한 범위에서만 진행하고, 필요한 경우 원래 값을 별도로 기록하세요.

프로그램은 쓰기 전 현재 값을 다시 읽고, 주소·범위·기능·워드 순서·값을 검토한 뒤 명시적으로 확인받습니다. 충돌 확인과 쓰기 후 다시 읽기, 이력 기록을 제공합니다. 검토 화면에 나온 장비·주소·전송할 값이 의도와 같은지 직접 확인하세요.

쓰기 기능은 FC05·FC15·FC06·FC16·FC22·FC23을 다루며 실제 사용 가능 여부는 장비에 따라 다릅니다. FC06·FC16은 읽기와 쓰기 사이에 다른 통신 주체가 값을 바꿀 수 있습니다. 이 두 동작을 한 번에 처리하는 원자적 작업으로 보장하지 않습니다. FC22도 대상 장비가 지원하는지 확인해야 합니다.

응답 지연이나 오류가 생겼다고 같은 쓰기를 바로 반복하지 마세요. 장비의 현재 값과 운전 상태를 먼저 확인하고 현장 담당자의 절차에 따르세요.

## 점검 종료와 제거

점검을 마칠 때는 필요한 설정과 기록을 별도 파일로 보관합니다. 진행 중인 읽기·검색·기록 작업을 중지하고 장비 연결을 해제한 뒤 프로그램을 정상 종료해 통신을 정리하세요. 브라우저 탭을 닫는 것과 프로그램 전체 종료는 구분해야 합니다. 탭을 닫았다는 사실만으로 통신이 종료됐다고 판단하지 마세요. 다른 통신 도구로 이어서 작업한다면 이전 작업이 끝났는지와 COM 포트 사용 상태를 확인하세요.

프로그램을 제거하려면 위 절차로 점검을 마친 뒤 Windows 설정의 앱 목록에서 Modbus Check를 선택해 제거합니다. 제거 화면의 안내를 따르고, 사용자 파일의 보존·삭제 여부를 확인하세요. 필요한 파일은 제거 전에 별도로 보관해야 합니다.

## 문제가 생겼을 때

통신이 되지 않으면 장비 전원과 케이블, 통신 설정과 대상 장비를 먼저 확인하세요. 통신은 되지만 값이 다르면 주소 기준, 기능 코드, 데이터 형식과 레지스터 순서를 확인하세요.

| 증상 | 먼저 확인할 내용 |
|---|---|
| TCP 연결 실패·시간 초과 | 전원·케이블·네트워크 경로, 장비의 IP·포트·Unit ID와 Modbus 서비스 설정을 대조합니다. |
| COM 포트 열기 실패 | Windows에서 포트가 인식되는지, 드라이버와 포트 번호가 맞는지, 다른 프로그램이 포트를 점유했는지 확인합니다. |
| Modbus 예외 응답 | 기능 코드·주소 영역·0/1 기준과 요청 수량이 장비에서 허용하는 범위인지 확인합니다. |
| 값이 비정상적으로 크거나 다름 | 자료형·부호·시작 주소·워드 순서, 필요한 구성 레지스터 수와 표시 설정을 대조합니다. |
| Binary 이름·설명이 예상과 다름 | 원본 Excel 파일을 보관한 상태에서 주소·Binary 타입, 주표의 `Bit 0:`~`Bit 15:` 비트명·설명 입력과 비트별 이름·설명 대응을 다시 확인합니다. |
| 트렌드에 문자열이 보이지 않음 | ASCII 문자열은 트렌드 대상에서 제외됩니다. 문자열은 주소 데이터와 읽은 내용으로 확인합니다. |
| 통신 검색에서 응답 없음 | 검색 범위와 통신 조건을 다시 확인합니다. 응답이 없다는 결과만으로 장비가 없다고 확정하지 마세요. |
| 기록 파일에 값이 없거나 차트와 다름 | 파일 기록 상태·저장 위치·크기와 개수 제한, 내보낸 시간 범위를 확인합니다. 브라우저 차트와 파일 기록은 별도입니다. |
| XLSX 차트에 일부 값이 보이지 않음 | 차트 표시 범위와 원시 데이터 시트를 대조합니다. 차트에서 제외된 값도 데이터에 남을 수 있습니다. |
| XLSX 저장 후 편집 지원이나 행 잠금이 다름 | 일반 XLSX 저장은 매크로를 제거합니다. XLSM 원본과 같은 자동 편집 동작을 가정하지 말고 편집할 때는 보관한 원본과 비교하세요. |
| 묶음을 줄인 뒤 구성 행의 설명이 다름 | 시작 행의 자료형·ASCII 바이트 수와 해제된 주소를 확인하고, 복원된 이전 설명이 의도한 주소맵과 맞는지 대조합니다. |
| Float64 선택 후 Excel 전체 멈춤 | 원본을 보관하고 해당 설치본의 알려진 문제를 확인하세요. 제보된 전체 멈춤은 아직 재현하지 못했고 해결 여부도 확인되지 않았습니다. |

통신 오류가 난 뒤 쓰기 작업을 반복하기 전에 현재 장비 값과 상태를 확인하세요. 설정을 한꺼번에 여러 개 바꾸기보다 주소·타입·통신 조건을 하나씩 대조하면 원인을 구분하기 쉽습니다.

## 사용 조건과 한계

개인 사용과 회사 업무용 사용은 무료이며 소스 코드는 공개하지 않습니다. 설치 파일의 재배포 또는 프로그램의 수정·재판매·OEM 제품에 포함하는 이용은 별도 허가가 필요합니다. 타사 라이선스에서 부여한 권리는 이 제한에서 제외됩니다. 설치본의 타사 라이선스 고지도 함께 확인하세요.

장비별 지원 기능과 통신 환경이 다르므로 사용할 장비의 매뉴얼과 실제 응답으로 확인해야 합니다. 실제 PLC·USB RS-485 변환기·현장 COM 환경의 호환성 검증은 아직 남아 있습니다. 모든 장비와의 호환이나 규제 준수를 보장하지 않습니다.

창의 네이티브 아이콘과 앱 식별자 검사는 통과했지만 작업 표시줄의 실제 화면 캡처 검증은 완료하지 못했습니다. 모든 실행 화면의 시각 검증이 끝났다고 판단하지 마세요. Node 보안 수정본은 공개 후 영향 검토와 회귀 시험을 거쳐 후속 버전에 반영할 예정입니다.
