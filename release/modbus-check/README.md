# Modbus Check

Modbus Check는 Excel에서 작성한 주소맵을 불러와 통신 확인과 기록으로 이어가는 BMS·MES 실무용 무료 도구입니다. 프로그램의 Excel 양식에 주소·자료형·설명·비트 설명을 정리하고, 미리보기로 검토한 설정을 앱에서 이어서 사용할 수 있습니다.

## 어떤 작업이 편해지나요?

- **Excel에서 주소맵 준비:** 프로그램의 양식에 주소·이름·자료형·설명을 정리하고, 편집용 XLSM 주표에서 Bit0~Bit15의 이름·설명을 직접 작성합니다. 32·64비트 값과 ASCII 문자열이 차지하는 행은 잠금·해제해 겹치는 입력을 줄입니다.
- **미리보기 후 가져오기:** Excel에서 작성한 주소맵을 미리보기와 검증 결과로 확인한 뒤 앱에 적용합니다. 검토한 이름·설명·자료형·비트 정보를 이어서 사용해 같은 내용을 다시 입력하는 작업을 줄입니다.
- **실제 수신값 대조:** 연결한 장비에서 읽은 값과 주소별 이름·설명·선택한 자료형을 함께 확인합니다. 정수·실수·HEX·Binary·ASCII 해석과 워드 순서를 장비 주소표와 비교할 수 있습니다.
- **점검 기록 정리:** 숫자 트렌드와 읽기 기록으로 변화를 살펴보고 CSV·기록 XLSX와 편집 가능한 Excel XY 차트로 정리합니다. BMS·MES 시운전 전후 같은 기록을 다시 검토하는 자료로 활용할 수 있습니다.
- **통신 설정 검색 보조:** Modbus TCP와 시리얼 RTU·ASCII에서 사용자가 정한 범위만 읽기 전용으로 검색합니다. 작업량을 검토하고 진행 중 취소할 수 있습니다.

통신 검색은 읽기 전용이며 장비의 값을 바꾸는 쓰기 요청을 보내지 않습니다. 검색으로 응답을 찾았더라도 장비 종류나 데이터의 의미까지 확인된 것은 아닙니다. 검색 결과를 연결 입력란에 넣은 뒤 장비 매뉴얼과 실제 값을 다시 확인하세요.

## 5단계로 시작하기

1. **설치:** 아래의 0.2.0-rc.7 사전 공개 설치 파일과 알려진 한계를 확인하고, 배포처·버전·SHA256을 대조한 뒤 설치합니다.
2. **설정하고 연결:** TCP의 IP·포트·Unit ID 또는 시리얼의 COM 포트·통신 조건을 확인하고 직접 연결합니다. 검색 결과를 채워 넣는 것만으로 자동 연결하지 않습니다.
3. **작은 범위 읽기:** 의미를 아는 주소부터 적은 수량으로 읽습니다. 주소의 0/1 기준과 실제 PDU 주소, 자료형·워드 순서를 장비 주소표와 대조합니다.
4. **기록과 트렌드 확인:** 필요한 읽기 기록을 시작하고 숫자형 값의 변화를 살펴봅니다. 브라우저 차트와 파일 기록의 상태를 각각 확인하세요. ASCII 문자열은 트렌드 대상에서 제외합니다.
5. **목적에 맞게 내보내기:** 읽기 기록은 CSV·XLSX로, 주소맵과 수신값 백업은 해당 Excel 내보내기로 정리합니다. 설정 파일을 다시 불러올 때는 미리보기·검증 결과를 검토하고 동의한 뒤 적용합니다. 파일 값을 현재 장비의 수신값이나 쓰기 기준으로 사용하지 않습니다.

## Windows 설치·실행·제거

Windows x64에서 실행하며 Chrome 또는 Edge로 화면을 사용합니다. 장비와의 통신은 같은 PC에서 실행되는 통신 처리 프로그램이 담당합니다. 처음에는 통신 설정을 직접 확인하고 연결해야 하며 자동으로 장비에 연결하지 않습니다.

배포된 설치 파일의 이름·버전과 SHA256을 먼저 확인하고 실행하세요. 설치 화면의 안내에 따라 설치한 뒤 바탕화면 또는 시작 메뉴의 Modbus Check로 실행하고 Chrome 또는 Edge에서 화면을 사용합니다. Node.js는 별도로 설치하지 않습니다. 장비의 통신 설정과 주소표는 별도로 준비하세요. Windows의 정확한 지원 버전과 설치본 변경 사항은 해당 릴리스 안내를 확인하세요.

제거 전에는 필요한 설정과 기록을 별도 파일로 보관하고, 진행 중인 읽기·검색·기록 작업을 중지한 뒤 장비 연결을 해제하고 프로그램을 정상 종료해 통신을 정리하세요. 브라우저 탭을 닫는 것과 프로그램 전체 종료는 구분해야 합니다. Windows 설정의 앱 목록에서 Modbus Check를 선택해 제거하고 화면 안내에 따릅니다. 사용자 파일의 보존·삭제 여부는 제거 안내를 확인하세요.

- 운영 중인 장비에서는 점검 범위와 통신 주기를 현장 담당자와 협의하세요.
- 읽기 점검부터 시작하고, 값을 쓰기 전에는 대상 장비·주소·값과 운전 영향을 다시 확인하세요.

## 주소맵·값·Excel 파일 구분

주소맵은 주소·이름·자료형·워드 순서·단위와 설명을 관리하는 설정입니다. Scale/Range와 Unit도 주소맵 메타데이터이며 값을 자동으로 공학 단위로 환산하지 않습니다. Float 소수 자리의 자동 또는 0~6자리 선택은 표시 설정이며 원시 값이나 쓰기 초안을 바꾸지 않습니다.

Excel 주소맵, 수신값의 시점별 백업과 시간 순서의 읽기 기록은 목적이 다릅니다. 파일을 불러올 때는 미리보기와 검증 결과를 검토하고 동의한 뒤 적용하세요. 파일에 담긴 값을 현재 장비에서 받은 값이나 쓰기 전 비교 기준으로 취급하지 않습니다.

편집용 XLSM의 주표에서 `Bit 0:`부터 `Bit 15:`까지 비트명·설명을 직접 입력하고 비트별 표시·이름·설명을 다시 불러올 수 있습니다. 32·64비트 값과 ASCII 문자열이 차지하는 구성 행의 잠금·해제를 지원하며, 묶음을 줄이면 이전 설명을 복원합니다. 수식처럼 보이는 이름도 텍스트로 보존합니다.

XLSM에는 비트명·설명 편집과 행 잠금·해제를 돕는 매크로가 들어 있습니다. 매크로가 없는 파일이 필요하면 Excel의 일반 ‘다른 이름으로 저장’에서 XLSX로 저장할 수 있습니다. XLSX에서는 매크로로 처리하던 자동 잠금·해제가 실행되지 않으므로 같은 편집 동작을 기대하지 마세요. 편집용 원본은 별도로 보관합니다. 앱에 별도 전달용 XLSX 버튼은 없습니다. 자세한 구분은 [사용 가이드](USER_GUIDE.ko.md)를 확인하세요.

rc.6 표준 양식의 실제 주소 목록은 PDU 0~500의 고유 주소 501개이며 누락·중복이 없음을 확인했습니다. 화면의 읽기 범위를 143개 또는 4개 주소로 설정해도 표준 양식의 주소 목록은 같습니다. rc.7의 공식 검수에서도 첫·마지막 PDU 0/500과 고유 주소 501개가 확인됐습니다. `No`는 순번이며 PDU 주소가 아닙니다. 주소 개수는 비트 보조 행과 서식용 빈 행을 빼고 고유 PDU 주소로 집계합니다. 이 결과는 표준 양식의 주소 목록에 관한 것으로, 현재 데이터 내보내기·로그나 전체 PDU 범위의 검증 완료를 뜻하지 않습니다.

## 쓰기 검토

쓰기 전에는 현재 값을 다시 읽고 주소·범위·기능 코드·워드 순서와 변경할 값을 검토한 뒤 명시적으로 확인합니다. 충돌 확인, 쓰기 후 다시 읽기와 이력 기록을 제공합니다. 설정이나 화면 표시를 바꾸는 것만으로 장비에 쓰지 않습니다.

장비가 지원하는 기능 코드와 현장 절차를 확인해야 합니다. FC06·FC16에서 값을 읽은 뒤 쓰기까지의 사이에는 다른 장치가 값을 바꿀 수 있습니다. 이 과정을 하나의 중단 없는 장비 작업으로 보장하지 않으며 FC22 지원 여부도 장비별로 확인해야 합니다.

## 지원 범위와 한계

장비마다 지원하는 기능 코드, 주소 표기, 데이터 형식과 통신 조건이 다릅니다. 사용할 장비의 매뉴얼과 실제 응답을 기준으로 설정을 확인해야 합니다. 실제 PLC·USB RS-485 변환기·현장 COM 환경의 호환성 검증은 아직 남아 있으며 모든 장비와의 호환이나 규제 준수를 보장하지 않습니다.

Float64를 선택한 뒤 Excel 전체가 멈춘다는 제보는 아직 재현하지 못했고 해결 여부도 확인되지 않았습니다. 원본 파일을 별도로 보관하고 작업 결과를 대조하세요. 일반 XLSX 저장과 매크로 제거 시험은 확인한 자료의 결과이며 모든 문서의 편집 동작이나 인쇄 모양을 보장하지 않습니다.

창의 네이티브 아이콘과 앱 식별자 검사는 통과했지만 작업 표시줄의 실제 화면 캡처 검증은 완료하지 못했습니다. 모든 실행 화면의 시각 검증이 끝난 상태로 안내하지 않습니다.
